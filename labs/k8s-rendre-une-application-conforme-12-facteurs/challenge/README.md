# Challenge: Make an application 12-factor compliant on Kubernetes

## The situation

The team delivered the application **`podinfo`** in the namespace **`douze`**.
It runs, but it breaks several of the twelve factors:

- its **configuration** is hard-coded in the container arguments;
- it writes its **state** on an `emptyDir` volume of the Pod;
- nothing protects in-flight requests when a Pod **shuts down**.

A **Redis** runs next to it, in the same namespace, reachable through the
Service `redis` on port 6379. The application does not use it yet.

The application's manifests are waiting for you in **`~/douze`**
(`deployment.yaml`, `service.yaml`). You are on the control plane, with
`kubectl` configured.

## What you must achieve

1. podinfo's configuration comes from a **ConfigMap generated by a Kustomize
   `configMapGenerator`**, whose name ends with a hash of its content,
   injected by `envFrom`. Nothing hard-coded in the arguments anymore.
2. The **state lives in Redis**: the Pod no longer carries a local state
   volume, and a value written to podinfo's cache survives the deletion of the
   Pod.
3. The podinfo container has a **`preStop`** hook.
4. A **Job `admin-seed`**, with the same image as the application, wrote the
   value **`graine-par-le-job`** under the key **`seed`** of the cache, and it
   is finished (Complete).

## Landmarks

podinfo reads its configuration from environment variables prefixed with
`PODINFO_`. The address of its cache is given by `PODINFO_CACHE_SERVER`, in the
form `tcp://<service>:<port>`. Its API writes to the cache with
`POST /cache/<key>` and reads back with `GET /cache/<key>`.

A `configMapGenerator` suffixes the ConfigMap name with a hash of its content:
changing a value creates a new ConfigMap, hence a new revision of the
Deployment. `kubectl apply -k <directory>` applies a kustomization.

A Job is immutable: it does not belong in the application's kustomization.

## How you will know it works

The tests read the Deployment, its volumes and its ConfigMap, write a value to
the cache, delete the Pod and read it back, then read the Job and the seed.

```bash
dsoxlab check k8s-rendre-une-application-conforme-12-facteurs
```
